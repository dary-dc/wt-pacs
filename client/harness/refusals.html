Back-to-back refusals

One RequestFrames whose every index is out of range, so the server answers with n FrameError messages back to back on the control stream. Every waiter must reject promptly with the server's reason; a waiter that only ends on the 15 s client timeout means a control message was lost.

Query: arm=ts|wasm · n=64 (refused asks) · wt=/hash= override /wt/dev-transport.json.
