## The worker's procedure (each hourly firing)

1. `git fetch origin --prune`. If the date is after 2026-11-13 23:59, write nothing and end with "queue closed".
2. Read every `docs/queue/<ROW>.md` status file (CORE-NEXT, a fixed routine, keeps one too; when it is stalled, resume it like a row, from its own prompt's task as recorded in its Resume) on `origin/claude/work-ledger`. A row is **running** when its state is
   `started` and its `heartbeat` is under 60 minutes old; **stalled** when `started` and older; **done** or
   **blocked** as written.
3. If twenty or more rows are running, end with "busy: <rows>" (the owner, 2026-11-11 01:15: the usage window is
   free, so rows run in parallel; it was two). A session started for one named row takes that row only.
4. Pick the first row in the table below that is stalled, or else the first with no status file whose not-before
   has passed and whose inputs exist and have not moved for 20 minutes (a row may say otherwise). Nothing to pick:
   end with "nothing due" and the next row's not-before.
5. **Claim it**: on `claude/work-ledger`, write `docs/queue/<ROW>.md` (the schema below) with `state: started`,
   commit, `git pull --rebase`, push. If the rebase shows the file already changed by someone else, drop the claim
   and go back to step 4 once.
6. Do the row. A stalled row is a **resume**: read its Resume section and its output branch, continue from what is
   pushed, and never redo pushed work.
7. Finish: `state: done` (or `blocked`, with why), its outputs, a result of at most 15 lines, and any owner
   decision. Push. End with a chat message under 200 words.

## No work lost (every row, every session)

* Commit and push to your output branch after every step that produced anything: a file, a test, a fix, a result
  row, a section of a document. Never hold more than about 20 minutes of unpushed work. A measurement pushes its raw
  rows as they land.
* After each push, update your status file: `heartbeat`, and the **Resume** section (what is done with its commits,
  what is next, the exact commands to continue). Push it. The next session can only continue from what is written.
* Before anything long (a build, a measurement, a big review), write the Resume first.
* When you sense the end (context filling, usage warnings, a time limit), stop starting new work: push, write the
  Resume, set `heartbeat`, end.
* Subagents you start push their own work the same way, to your branch or theirs, before they return.

## Decided approaches (keep them; never reopen them)

* The browser decodes the optimal-quality (OQ) view through WebCodecs. dav1d-WASM is only a fallback after WebCodecs
  refuses a config or fails to decode, and the overlay names the route and why.
* Stored depth D > 10: the OQ view is the depth cut to 10 bits. D ≤ 10: coded at its own depth. Full fidelity is the
  exact HTJ2K frame on an explicit Lossless request, bit for bit.
* AV1 only for cine-like series (one consecutive dimension). No low-resolution preview; a preview is tiny and full
  size only. XXH3 is the frame check.
* The target is mobile on lossy wireless: remove work, no server caps, no TCP for the fill unless proven. Faster
  fill and lower on-demand latency both count; the fill and on-demand asks are optimized separately for now.
* The client cache is OPFS, with no re-decoding.
* Lab code stays on its line branch while used; `main` stays deployable. Resilience is phase 2, parked.
* A proposal names its deciding measurement and is judged on its total effect. A design shows what decides each
  choice across a band and stays switchable.
* Nothing is deleted by interpretation: a removal names its items and waits for the owner's yes.
