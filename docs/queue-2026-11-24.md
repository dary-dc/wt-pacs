## The worker's procedure (each firing)

1. `git fetch origin --prune`. If the date is after 2026-11-27 23:59, write nothing and end with "queue closed".
2. Read every status file `docs/queue/<ROW>.md` on `origin/claude/work-ledger` for the rows of this file. A row is
   **running** when its state is `started` and its `heartbeat` is under 60 minutes old; **stalled** when `started`
   and older; **done** or **blocked** as written.
3. If **six** or more rows of this file are running, end with "busy: <rows>". A session started for one named row
   takes that row only.
4. Pick the first row in §Rows that is stalled, or else the first with no status file whose not-before has passed,
   whose needs are met (or whose latest has passed), and whose inputs have not moved for 20 minutes. Never take a
   row marked **held**, **local** or **the owner's**, nor a review of a row whose status file's `by:` names your
   session (a status file without `by:` is taken as written by no one). A row marked **(Fable)** is taken only by a
   Fable session, **one Fable row of this file running at a time**, no daily limit (amendment 27 item 3); every other row
   only by an Opus session. Nothing to pick: end with "nothing due" and the next row's not-before.
5. **Claim it**: on `claude/work-ledger`, write `docs/queue/<ROW>.md` (the schema below; the row's name without its
   model mark) with `state: started`, commit, `git pull --rebase`, push. If the rebase shows the file already changed
   by someone else, drop the claim and go back to step 4 once.
6. Do the row by its brief. A stalled row is a **resume**: read its Resume and its output branch, continue from what
   is pushed, never redo pushed work. At each push, fetch this file again and re-read the brief.
7. Finish: `state: done` (or `blocked`, with why), its outputs, a result of at most 15 lines, any owner decision last;
   update the row's line doc on the output branch (`docs/lines/<line>.md`, its date). Push. End with a chat message
   under 200 words.

A row that runs at its latest without its needs says what was missing, and a page or verdict written so marks its
recommendation **provisional**.

## No work lost (every row, every session)

* Commit and push to the output branch after every step that produced anything. Never hold more than about 20
  minutes of unpushed work. A measurement pushes its raw rows as they land.
* After each push, update the status file's `heartbeat` and **Resume** (done with commits, next, the exact commands)
  and push it. Before anything long (a build, a measurement, a big review), write the Resume first.
* When you sense the end (context, usage, a time limit), start nothing new: push, write the Resume, set `heartbeat`.
* Subagents push their own work the same way before they return.
