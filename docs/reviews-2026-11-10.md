## CORE-FIXES-REVIEW (independent review of #336, #337, #330)

No PR into `claude/core` has CI: `.github/workflows/gate.yml` runs only on `main` and `claude/av1-unified-mainbase`, so
#336, #337 and #330 have no check runs. CI's `deploy` job was therefore run here by hand, step by step (docker 29.9.2,
4 cores), and the full gate likewise.

### `claude/core-ci-deploy` (#336): approve

* **Reproduced, then fixed.** On `claude/core` (2e6fa5b2), `docker build --target build` fails as CI did:
  `failed to read /src/client/native/Cargo.toml`. With the fix, every step of CI's `deploy` job passes: `server`
  (series-server built in 1 m 36 s, no `native-client`, `wgpu` or `winit` compiled), `wasm`, `web`,
  `deploy/check_equivalence.sh` ("equivalent on 11 paths"), and the viewer check through `compose up` on the 3-frame
  `grey-16.j2c` series, ts and wasm clients ("every frame complete, exact and drawn"). One local change was needed:
  `NOFILE=20000 MEMLOCK=8388608`, because this container's hard limits refuse compose's 65535.
* **In the image's workspace, or out of it?** In it, copied, as the PR does. Taking `client/native` out of the
  workspace the image builds breaks `--locked`. Deleting the member from `Cargo.toml` makes `cargo metadata --locked`
  fail with "cannot update the lock file", so the image would need a lock file of its own. The crate is not compiled
  for `-p series-server`, and no stage ships it. The cost is a server rebuild in the image whenever `client/native`
  changes (it is 172 KB of source).
* Low, not fixed: the commit message says "copied for the manifest only", but the whole directory is copied, which
  the `[[example]]` needs (the PR body says so). `lab/container-bench/Containerfile.dockerread` also misses
  `client/native`, and has missed `lab/cc-classify` and `lab/server-telemetry` since `main`. It is a lab file outside
  CI, so its breakage predates this branch.
* Gate: see the end of this section.

### `claude/core-int8` (#337): fixed on `claude/core-int8-fixes` (#345)

The port of `faf6932d` is faithful: the code and tests are identical, and only the two doc pointers changed. Its
tests fail without it, as stated: on core's reader 10 of 245 fail, `merge_test.py` gives 137/142, and
`from_dicom_test.py` fails 1.

* **High, fixed: the rule is incomplete.** A signed source under 8 bits whose offset passes 128 still wraps in Int8,
  and its digest wraps with it, so the check passes. Examples: −200…−100 (7 bits, offset 200) and −129…−100.
  Reproduced in Node: first sample 56 for −200, and 127 for −129. The rule is now whether −offset … 2^bits − 1 −
  offset fits a byte, in `av1-frame.js` and `ingest.py`'s `wide`. This is on mainbase too (`faf6932d`); it is not
  fixed there.
* **Medium, fixed: native disagreed after the port.** `client/native/src/decode.rs` narrowed every payload of 8 bits
  or fewer to one byte. The writer's digest is now over two bytes, so `native-fill` would report every off-centre
  signed series as a failed check. Native now uses the same rule (`Payload::wide`).
* Tests: the reader and digest tests gained the two ranges, and the native test is new. Mutants killed: the old
  rule in each of the three, and core's `p.bits > 8` in native. Not caught: `payload()` calling `p.bits > 8`
  instead of `p.wide()`. No signed off-centre golden payload exists, so that call is checked by reading only.
  `cargo test -p native-client --features decode --lib decode`: 3 passed (the committed-digest test included).
* Not fixed, outside this diff: `client/paint/paint-worker.js` `format()` refuses every signed frame of ≤ 8 bits,
  so a signed series that fits Int8 is decoded and checked but never painted, AV1 or HTJ2K. Native's `window.rs`
  sizes a frame from `bitsStored`, while decode sizes it from the payload, so a centred signed 8-bit payload from a
  12-bit source mismatches.
* Not checked: anything through a codec or a browser for a signed off-centre series. The fixtures are synthetic
  1-row ranges, as on the source branch.

## DEPTHCUT-REVIEW: `claude/oq-depth-cut`, `7eefa997`..`6f61ff0b` (#328)

**Verdict: fixed on `claude/oq-depth-cut-fixes`** (draft #348 into `claude/oq-depth-cut`). No code bug was found. The
code follows the owner's decisions:
* WebCodecs first for every optimal-quality frame; dav1d only after a refusal, and the refusal is named on the frame
  and in the overlay.
* D ≤ 10 is never cut (refused in `ingest.py` and in `pair.js`).
* The cut is `min((v + 2^(D−11)) >> (D−10), 1023)`, painted through a table at c · 2^(D−10).
* *Lossless* only once the exact frame is checked and painted.

The fixes are tests and one docs correction.

**Medium**
* `client/view/controller.js:8`: if `asPainted` drops `cut`, the painter windows the 10-bit codes as stored values
  and every test still passes. Fixed with a test (`controller.test.mjs`, the painter's table at full depth).
* `client/decode/decoder.js:108`: if `decoder.js` drops `refusal`, the refusal never leaves the decoder, so the
  overlay would never name it, and no test failed. Fixed with a test (`decoder.test.mjs`, stand-in dav1d glue).
* `client/decode/av1.js:55–66`: a WebCodecs failure on a frame inside a group, after its keyframe decoded there, is
  not recovered. dav1d never saw the keyframe, so the rest of that group fails by name up to the next keyframe.
  Read from the code, not run. Documented in `payload-format.md` §Decoder choice. A fix (re-feeding the group to
  dav1d from its keyframe) is structural, so it is left for the owner to decide.

**Low**
* `docs/av1/payload-format.md` §Depth cut: "a rounding error of at most 2^(D−11)" is false at the clamp. 4095 at
  D 12 is off by 3. Corrected in place. `docs/lines/optimal-quality.md` §Terms on `main` repeats the claim and still
  needs the same correction.
* `ingest/coded-frames/lossy_test.py`: two gaps, both closed with checks. Nothing pinned the cut series' own
  `bitsStored`, and nothing tested the refusal of a signed set.
* `client/paint/paint-worker.js:217`: `frame.cut` in the table key is redundant, because a frame's cut never
  changes. The mutant that drops it is equivalent. A possible simplification; left as it is.

**Mutants.** 33 run, all killed once the fixes landed. They cover:
* the route: dav1d taken without trying WebCodecs, a refusal not recorded, the refusal not kept for the worker;
* the cut's rounding: truncated, half-down, no clamp, a fixed shift;
* the window table at D 11, 12 and 16 (hard-coded D 12, odd D off, a scaled window, a half-code centre);
* a 10-bit series cut, in the client and in the ingest;
* an early *Lossless* label, in three forms;
* a jump into a group at G 1, 8 and 16 (only the frame asked, the group shortened at 16, a group frame sent to any
  decoder).

One mutant is equivalent with respect to the label: an unchecked exact frame shows *fetching lossless…*, never
*Lossless*.

**Browser run** (headless Chromium, SwiftShader, page and worker views). Fixtures, both at Q 8 G 8 and ingested here:
`dbts_a1` as a 12→10 depth cut (56 frames) and `dbts_b1` at 10 bits (50 frames).
* Every frame of both took `av1-webcodecs`, as the overlay showed while stepping through each one.
* `l` gave *Lossless check failed · optimal quality shown*. This is expected: OpenJPH-WASM is not built here, so the
  exact frame could not be decoded, and the label correctly did not say *Lossless*.

**Contract.** The ingest writes `lossy {q, g, depth: 10, bitsStored: 12}`, the series' `bitsStored` 12 and
`exactSeries`, with no `digests`. The 10-bit series gets `lossy {q, g, depth: 10}`. `pairOf` and `checkPair` accept
exactly these and refuse the variants they should.

**Could not check**
* The full `scripts/gate.sh`: there is no wasm-pack here (its download was refused) and no Docker for the decoder
  builds. I ran a copy of the gate with `--no-browser --quick`, minus the WASM-transport prerequisite, the
  worker-safe check and the transport contract, and it passed. The absence checks, `run_browser.sh` and
  `run_check.sh` were not run.
* dav1d-WASM in the browser (the stored form's real fallback), a real *Lossless* match, the quality of the cut, and
  `dbts_c1`.
