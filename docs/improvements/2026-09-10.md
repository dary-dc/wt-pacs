# Improvements — 2026-09-10: first-byte wait, not another CPU cut

**Branch:** `cursor/latency-real-computer-093d` · **Status:** measured on this host.
Front door: [`README.md`](README.md).

**Brief.** Move the wait a real client sees. `claude/serene-rubin-wakfg7` already
closed the CPU / LTO / crypto / MTU / warm-`fadvise` path on a workstation. This
pass does not repeat it. The leftover wait: the server held the first ask and
the first frame read behind `open_uni`.

**Tier.** T2-local: 4 vCPU KVM (Xeon, AES-NI / VAES), ext4, `RWF_NOWAIT` honoured
(`read_fast_path=preadv2`), localhost, no shaping. Relative comparisons only.
This box saturates on the loopback send path (prior report: 225–284 MB/s).
Nothing past that is claimed.

## What `claude/serene-rubin-wakfg7` already falsified

Read first: their `docs/improvements/2026-09-10.md` and
`docs/serving-cells-and-run-variance.md` (PR #27). Do not re-derive.

| What they tried | Real-computer result | Why not again |
| --- | --- | --- |
| `lto = "fat"`, `codegen-units = 1` | CPU/frame −4 to −8 %; workstation e2e **indistinguishable** from `main` (native); fill **+7.5 %** under Chromium | CPU moved; client wait did not |
| `aws-lc-rs` vs `ring` on VAES | +3–5 % CPU at 32 KB, tie at 250 KB, +10–18 % RSS | tie or loss |
| `max_udp_payload_size` past 1472 | Chromium advertises 1472; 0 datagrams above that | closed for browsers |

They also showed `serve_us` depends on the client (native 2.18× browser on the
same server) and that quoting a median from one batch against another is the
sequential-arms error. This pass interleaves. Latency only.

sliding 4 MiB window and force-pool overlap, and **made wall worse** on 16 KiB

## What shipped

`FrameOut::begin` starts the shared uni at session accept. `accept_bi` and the
ask reader run without waiting for it. The first `send_frame` awaits the uni, so
the first read overlaps the handshake. Per-frame mode is unchanged.

Product clients (TypeScript, WASM) already send the first ask as soon as the
bidi exists. The native `server_ab` client used to wait for `accept_uni` first;
`--ask-first` is the product shape.

Invariant, mutated once: `shared_uni_arrives_before_the_client_opens_control`
fails if `begin` is moved behind `accept_bi` (5 s timeout).
`an_ask_before_the_media_uni_is_accepted_is_still_served` is the product path.

Not taken: mmap (ADR), streaming a frame before it is whole, warm `fadvise`,
LTO, MTU, `aws-lc-rs`, fill `in_flight` 2 (PR #28 wall regression).

## Measurement

Interleaved A/B, arm order reversed every repeat. No page-cache drop. Fixture
`lab/fixtures/frames_32k` (80 × 32 KiB) unless named. Driver
`server_ab --ask-first` against `/tmp/exact-server-main` (`main` at `495ccd6`)
and this branch. One server process per run, one session per run.

### Native, `--ask-first`, on-demand depth 1, 1 ask — 16 repeats

Ask-to-receive (`p50_ns`) is the product wait after the bidi exists. `wall_ns`
includes connect.

| statistic | main | branch | paired median | signs (branch faster) | verdict |
| --------- | ---: | -----: | ------------: | --------------------: | ------- |
| ask-to-receive p50 | 247 µs | 208 µs | **−12.5 %** | **13/16** | direction, not a 28.5 % resolution |
| ask-to-receive p10 across runs | 199 µs | 195 µs | — | — | **tie** |
| session wall p50 | 1.45 ms | 1.46 ms | −2.4 % | 11/16 | **tie** (connect dominates) |

The 13/16 sign on ask-to-receive is the overlap this change can see on
localhost: `open_uni` is tens of microseconds here, inside a ~200 µs ask.
**p10 across runs does not separate.** Session wall is connect-bound and does
not move.

On a path where `open_uni` is one RTT, the same overlap is that RTT. That
regime was not run here. Do not quote the −12.5 % as a workstation number.

### Chromium fill, product TypeScript client, 80 × 250 KB — 10 repeats

Tried the parked BYOB lever ([`2026-09-08.md`](2026-09-08.md)): media
`getReader({ mode: "byob" })` so the envelope is the stream buffer. Same
server, interleaved bundles, telemetry off, `wall_ms` from the harness cell
clock (after connect).

| statistic | main | branch (BYOB) | paired median | signs | verdict |
| --------- | ---: | ------------: | ------------: | ----: | ------- |
| fill wall | 59–72 ms | 59–71 ms | **0 %** | 3 / 4 / 3 (better / worse / tie) | **tie** |

Every run delivered 80/80. The accumulator copy the 2026-09-08 probe bounded
at 8–10 % of client *self time* does not appear in fill *wall* on this host
(transfer-bound, ~60–70 ms). **BYOB was not kept.** The TypeScript client on
this branch is `main`'s.
