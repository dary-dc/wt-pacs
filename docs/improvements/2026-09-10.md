# Improvements — 2026-09-10: first-byte wait, not another CPU cut

**Branch:** `cursor/latency-real-computer-093d` · **Status:** measured on this host.
Front door: [`README.md`](README.md).

**Brief.** Move the wait a real client sees. `claude/serene-rubin-wakfg7` already
closed the CPU / LTO / crypto / MTU / warm-`fadvise` path on a workstation. This
pass does not repeat it. Two leftover waits sat on the product path: the server
held the first ask behind `open_uni`, and the TypeScript client copied every
frame through an accumulator.

**Tier.** T2-local: 4 vCPU KVM (Xeon, AES-NI / VAES), ext4, `RWF_NOWAIT` honoured,
localhost, no shaping. Relative comparisons only.

## What shipped

### 1 · Shared uni starts at session accept

Product clients (TypeScript, WASM) open the control bidi and send the first ask
without waiting for the media uni. The server used to `accept_bi`, **then**
await `open_uni` through ready, **then** start the ask reader. The first ask
could already be in the QUIC buffer; the first read could not start.

`FrameOut::begin` starts the shared uni at accept. `accept_bi` and the ask
reader run without waiting for it. The first `send_frame` awaits the uni, so
the first read overlaps the handshake. Per-frame mode is unchanged.

Invariant, mutated once: `shared_uni_arrives_before_the_client_opens_control`
fails if `begin` is moved back behind `accept_bi` (5 s timeout).

### 2 · TypeScript media pump uses BYOB when the stream allows it

The parked BYOB lever ([`2026-09-08.md`](2026-09-08.md) §P2 / ledger §4) deletes
the accumulator copy on the product TypeScript path. Chromium 141 WebTransport
uni streams support `getReader({ mode: "byob" })`. The default-reader path
stays as fallback. WASM is unchanged this pass (it already copies once into a
JS `Uint8Array`).

Invariant, mutated once: `read-media.test.ts` fails if `readExactByob` returns
a short view (`length 63` on a 64-byte payload).

Not taken: mmap (ADR), streaming a frame before it is whole, warm `fadvise`,
LTO, MTU, `aws-lc-rs`, fill `in_flight` 2 (PR #28 wall regression).
