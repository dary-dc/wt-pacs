## 2 · What the re-runs corrected

1. **Prerender was a driver artefact, not a container limit.** The probe drove Chromium through
   Playwright; the browser's reason, read from the DevTools `Preload` domain, is
   `PrerenderingDisabledByDevTools`, headful under `Xvfb` included. Launched with no driver,
   headless Chromium 141 prerenders. **The answer:** while prerendering the page loads, fetches
   its config, imports the transport module and calls the dial at 44–85 ms; the WebTransport
   session and the worker's first message both land ~20 ms after activation, never before.
   Corrected in [`../rig-limits.md`](../rig-limits.md) §8, [`../../lab/prerender/`](../../lab/prerender/),
   the handoff, queue row 41 and [`2026-09-18.md`](2026-09-18.md) S20.
2. **`lab/scripts/first_ask_cells.sh` read the wrong field.** W2 (`edd006f`) added
   `fill_ms median=` to the probe's line after W1 had run; the script's greedy `sed` then took the
   last `median=`, so every arm but `filled` printed 0.0 and `filled` printed its fill time as its
   ask. W1's numbers predate the change and reproduce (§1). Fixed by anchoring on
   `ask_to_last_byte_ms`; `controller_cells.sh` already anchored.
3. **The transport docs described another branch's server as this tree's.** The chunked `Bytes`
   send path, the GSO patch, the PGO script and `--prefault true` are on
   `claude/clever-curie-flm0wi`, whose `server/` was not merged (queue row 35); this tree's
   `frame_out.rs` sends `write_all` in 64 KiB slices and `--prefault` is a no-op (`main.rs`).
   Corrected in [`../transport/README.md`](../transport/README.md) and
   [`transport-conclusions.md`](../transport/transport-conclusions.md); the CPU-per-byte figures
   in those rows are that branch's.
4. **D4 is still open** (2026-09-08): `dev-server.py` answers 200 for `server/dev-cert/key.pem`
   and `.git/config`. Reproduced, not fixed — it waits on the decision [`README.md`](README.md)
   lists.

## 3 · What is new

* **A prerendered viewer hides the page half of a cold open, not the dial.** The 3.6 round trips
  before the dial that R2 counts can run before the click; the dial's 3.0 cannot, and nothing that
  boots in a worker can. A page that dials at head loses nothing by being prerendered. **Decided
  by:** whether the viewer's page can be prerendered from the worklist at all — the display-library
  half — and a real profile. Not measured: a main-thread `WebAssembly` compile while prerendering
  (the product's decoders live in workers, so they wait too).
* **`check_equivalence.sh --local`** checks the deploy config without a container runtime, so the
  template is now covered wherever `nginx` installs. It starts with three "duplicate extension"
  warnings from the template's `types` override — cosmetic, unchanged.
* **This container image carries `Xvfb`** and a headful Chromium starts under it. Prerender did
  not need it in the end; anything that does need a display can have one.
* **The container's tooling:** `apt-get` works through the proxy (nginx installed from it), and
  `docker` is a binary without a daemon, so the built image is still unrun here.
