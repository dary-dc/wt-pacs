## 2 · The hole: two steps pass at half strength, and still say `GATE OK`

Both client steps check the TypeScript arm always and the WASM arm *only if* `client/transport-wasm/pkg/`
happens to exist. The gate never builds it. On a checkout that has not built the WASM client by
hand — which is every fresh container, and the workstation, which has no npm — the gate reports:

| | pkg/ absent | pkg/ present |
| - | - | - |
| worker-safe | `no client artifact reaches for window (1 checked)` | `(2 checked)` |
| conformance | `17/17 checks passed across 1 implementation(s) — one arm was skipped` | `34/34 across 2` |

Both then exit 0, and the gate prints `GATE OK`. The step is titled *(both implementations)*.

This is not silent — conformance says "one arm was skipped", worker-safe prints a count — but
it is not fatal either, and a reader scanning for `GATE OK` will not see it. The arm that goes
unchecked is the one with the history: `3396c28` fixed the WASM client reading its clock off
`window`, which returned 0 inside a worker rather than raising, and `check_worker_safe.sh` exists
because of that bug. It is the arm most worth checking and the one that skips.

Building it here cost **1 m 41 s** for the pkg, on top of ~2 min to `cargo install wasm-pack` and
3 s for the `wasm32-unknown-unknown` target. Making the gate hard-require it would roughly double
the cold gate and add a prerequisite the README does not name ([T6](2026-09-08.md#t--tooling)).
That is a contributor-facing decision, not a local fix, so it is in
[`cloud-queue.md` §Blocked](../cloud-queue.md#blocked) rather than done here.

## 3 · The gate does gate

A green gate is worth what it catches, so each kind of step was broken on purpose.

| Mutation | Caught by | Result |
| -------- | --------- | ------ |
| 40 comment lines prepended to `common/fod/src/lib.rs` | step 1 | `1 file(s) over budget`, exit 1 |
| `window.performance.now()` added to `session.ts` | step 3 | names file and line, exit 1 |
| `frame_head` counts one window, not the codestream | step 6 | **5 tests fail**, incl. `head_counts_the_whole_codestream_not_one_window` |
| `watchClosed()` returns early (undoes L4) | step 4 | `FAIL: a close is noticed from the session…`, 33/34, **whole gate exits 1** |

`set -euo pipefail` carries the conformance runner's exit code through `| tail -2`, so the gate
stops at the failing step rather than running on.

**One mutant survived:** `READ_WINDOW` 64 KiB → 63 KiB changed nothing — all 50 tests passed. The
tests use it symbolically (`const SHORT: usize = READ_WINDOW / 3`), which is the right call for a
tuning constant: pinning its value would test the knob, not the behaviour. Recorded as a
deliberate non-finding, not a gap.
