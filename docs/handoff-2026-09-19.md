**The one cell where `main` still wins:** 250 KB, depth 1, four sessions — p99 2.2 ms → 27.9 ms
and throughput −29 %, a probe timeout on a lost frame tail. `main` carrying only the quinn
patch reproduces it to within 1 %, so the **GSO cap is the whole of it**. It needs depth 1 *and*
a path fast enough for a 45-packet burst to form; the target's pacer sits at its 10-packet
floor, so the target cannot produce it (derived from `pacing.rs`, not measured). A client
window of ≥ 2 also removes it by construction.

**The synthesis worth carrying forward:** §9 buys **cost per session** — real, large, and
invisible to a viewer, because Chromium's receive path is the ceiling on this rig. The client
window buys **the wait**. They are complementary, and only the window reaches the browser.

## 2 · Traps this session fell into, each once

- **Revert the whole commit's footprint, not the parts you read.** §8's runtime flavor was three
  lines from code I edited and I missed it. `git show <commit> --stat` before and after.
- **A single-threaded server reads exactly like lock contention**: CPU per ask down, context
  switches down, throughput down. If a result has that shape, check the runtime before believing
  the mechanism story — it is very convincing and it was wrong.
- **Fetch before you build.** T6 step 1 had been done three days earlier; the branch was 30
  commits ahead and I wrote a second relay with the same name before noticing.
- **A `cp` after a failed build silently copies the previous binary.** One arm was a duplicate of
  another for a whole run. Check the build's exit status before copying an arm out.
- **Sequential browser arms lie** — `CLAUDE.md` says so and I did it anyway the first time. The
  numbers in §1 are interleaved with the order reversed each repeat.
- **`browser_cell.py` columns**: `us_per_frame` is field 5; field 6 is `delivered`.
- **`pkill -f <pattern>`** kills the shell whose command line holds the pattern. Already in the
  2026-09-14 handoff; still true; kill by pid from `ps -eo pid,args`.
