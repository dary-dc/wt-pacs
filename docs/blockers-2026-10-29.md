## 1. #213 fixes the port race; #193's gate

**What failed.** #193's CI `gate` (run `40555079391`) failed in `cargo test -p series-server --features telemetry`.
The failing test was `transport::server::tests::a_lost_first_flight_is_repeated_whole`, which panicked with "the
server never bound port 58487".

**The race.** `free_port()` bound port 0, read the port and released it, and the server bound it later.

* **Another socket takes the port first:** the server's bind fails with `EADDRINUSE`.
* **`until_bound`'s probe holds the port at the instant the server binds:** the server's bind fails, and the test
  waits out its deadline: "never bound".

#213 hands the server the fixture's own bound UDP socket and TCP listener, so the port is never free.

## 3. The request-log fix: keep #210's line and #229's buffering

There are two causes, and the copies split along them.

* **The writer, `server/dev-server.py`.** `print()` writes a line and its newline apart, so two request threads merge
  lines and the viewer check misses both files. This is the failure seen: 3 in 9 runs in #212's review.
  * #210 `cfcb32eb` writes `print(f"GET {self.path}\n", end="", flush=True)`.
  * #212's `cff900bd` rewrote its own fix as #210's line, byte for byte, comment included. The two merge cleanly
    (checked).
  * #238 (core) has the same code with another comment: one conflicting line.
  * #112 (2026-10-18) has `sys.stdout.write` + `flush`: one conflicting line.
* **The reader, `client/viewer/check.mjs`.** #229 (core) keeps the unfinished line across stdout chunks. That is
  another cause: a pipe read can end inside a line even when each line is one write. It was not seen failing.

**Do they conflict?** Not in any way that matters. Every copy of the writer fix changes the same line in the same
way, and the textual conflicts above are over its comment alone. #229's change is in another file.

* **Keep #210's `dev-server.py` line**, which #212 already carries. #238 and #112 take it when they meet it.
* **Keep #229's `check.mjs` buffering** as well. It guards the other half.
