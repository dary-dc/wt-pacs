## What this program questions

The inventory was sorted by what can still change each answer, not by line, and that changed the plan:

1. **Most owed decisions need no new work, only a page.** Their evidence exists and is scattered over line docs,
   PR bodies and status files. Those get one page row each. The full chain (theory, protocol, build, review, run,
   verdict) is kept for the questions where a cloud run can still refute something: delivery, the exact frame's
   layout, the reports' missing cells, the engines.
2. **One phone decides nothing about phones.** A device result carries only through a model that predicted it
   first (DEVICE-THEORY), so every page that depends on a device gives a range per device class, labelled derived.
3. **The route need not be one.** Every option file so far compares routes for *the* phone. Choosing per device
   class or per session from a measurement is an option nobody has worked out (ROUTE-POLICY).
4. **"Visually lossless" may be the wrong promise.** The noise rule's anchor is unresolved on 15 of 19 volumes and
   the encoder removes noise at the rule's Q (`docs/lines/codecs.md` §Open 10). VL-CRITERION asks what the view may
   claim with no reader at all, and includes claiming nothing.
5. **The check proves less, and more, than its label says.** INTEGRITY-MODEL starts from the faults, not from the
   digest we happen to have.
6. **A hole in the scope.** "What series that are not cine-like get is not stated yet" (`docs/client/design.md`
   §Open, last line) had no owner and no row (NON-CINE-OPTIONS).
7. **A question the cloud cannot answer still gets a page**: it says exactly what one device session, one machine
   with a GPU or one reader study must measure, and what each outcome would decide.

## The worker's procedure (each firing)

1. `git fetch origin --prune`. If the date is after 2026-11-28 23:59, write nothing and end with "queue closed".
2. Read every status file `docs/queue/<ROW>.md` on `origin/claude/work-ledger` for the rows of this file. A row is
   **running** when its state is `started` and its `heartbeat` is under 60 minutes old; **stalled** when `started`
   and older; **done** or **blocked** as written.
3. If four or more rows of this file are running, end with "busy: <rows>". A session started for one named row
   takes that row only.
4. Pick the first row in §Rows that is stalled, or else the first with no status file whose not-before has
   passed, whose needs are met (or whose latest has passed), and whose inputs have not moved for 20 minutes. A row
   marked **(Fable)** is taken only by a Fable session (`claude-fable-5-2`), at most one Fable row a UTC day counted
   over this file and the client queue together; every other row only by an Opus session. Nothing to pick: end
   with "nothing due" and the next row's not-before.
5. **Claim it**: on `claude/work-ledger`, write `docs/queue/<ROW>.md` (the schema below; the row's name without its
   model mark) with `state: started`, commit, `git pull --rebase`, push. If the rebase shows the file already
   changed by someone else, drop the claim and go back to step 4 once.
6. Do the row by its brief. A stalled row is a **resume**: read its Resume and its output branch, continue from what
   is pushed, never redo pushed work. At each push, fetch this file again and re-read the brief (amendment 21).
7. Finish: `state: done` (or `blocked`, with why), its outputs, a result of at most 15 lines, any owner decision
   last; update the row's line doc on the output branch (`docs/lines/<line>.md`, its date). Push. End with a chat
   message under 200 words.

## No work lost (every row, every session)

* Commit and push to the output branch after every step that produced anything. Never hold more than about 20
  minutes of unpushed work. A measurement pushes its raw rows as they land.
* After each push, update the status file's `heartbeat` and **Resume** (done with commits, next, the exact commands)
  and push it. Before anything long (a build, a measurement, a big review), write the Resume first.
* When you sense the end (context, usage, a time limit), start nothing new: push, write the Resume, set `heartbeat`.
* Subagents push their own work the same way before they return.

Status file schema, `docs/queue/<ROW>.md`. A row's name is new: none here reuses a name in `docs/queue/` (a reused
name hid BRIEF-WED for five hours on 2026-11-18).

  into `claude/unified` of amendment 26, which only the DOCS-SYNC rows make. No close of a PR, no delete of a branch

  2026-11-16, and target it; say so in the PR body. Search the open PRs first: a question that already has a PR is

  file, with no PR unless its brief asks. A row whose input is on a branch `claude/unified` does not carry yet
  reads it there (`git show origin/<branch>:<path>`); §Rows names the branch.

* Essentialist code, the comment budget (`scripts/comment_budget.sh`), one name per concept (`docs/glossary.md`), a
  failing test before each fix, **mutate every new test** and say which mutants it killed.
* **A review row per build and per theory**, by a session that wrote none of it: each test fails without its change
  (revert and see), the change touches nothing else; for theory, every quoted source fetched at its pinned revision

  and the complete commands for a local run, sets `blocked`, and asks the owner nothing.
* Measurement (`CLAUDE.md` §Measurement): the protocol is pre-registered and written by a different session than the

* Sources: every claim about a standard, browser, codec, chip or tool quotes its official source verbatim, with URL,

* Phone runs are the phone session's, on the owner's device; GPU runs are on the owner's machine; reader studies are
  no agent's. A row may write their protocols, never run them.

## Decision pages

One file per question, `docs/decisions/<page>.md` on `claude/reviews-2026-11-28` (from `origin/claude/unified`; one
draft PR into `claude/unified`, "do not merge: decision pages", opened by DECISIONS-OPEN). A page is written by a
session that ran none of its question's rows, from pushed results only; it runs nothing. Its form, in this order,
the first four on one screen:

1. **The question**, in plain words, and why it is the owner's.
2. **The recommendation**, one sentence, and **the owner's yes or no**: what a yes changes (the PR to merge, the row
   to queue, the default to set), what a no leaves.
3. **The options**, a table: each with its numbers, every number labelled source, theory, derived or measured and
   linked to where it was produced.
4. **Where it holds**: the fixtures and their limits; then the population (devices, engines, links) the result is
   carried to, by which model, and that model's tested predictions, misses included.
5. **The mechanism**: why the numbers come out this way, in the fewest words that let the owner check the logic.
6. **What would change the recommendation**, and the one measurement that would show it (a device, a GPU, a reader).
7. **What it would reopen** among §Decided approaches, if anything.
8. **Rows and links**: every row, PR and file behind the page.

A page whose question's rows are not all done by its date is written from what is pushed, names what is missing,
and marks its recommendation **provisional**.
