## The worker's procedure (each firing)

1. `git fetch origin --prune`. If the date is after 2026-11-28 23:59, write nothing and end with "queue closed".
2. Read every status file `docs/queue/<ROW>.md` on `origin/claude/work-ledger` for the rows of this file. A row is
   **running** when its state is `started` and its `heartbeat` is under 60 minutes old; **stalled** when `started`
   and older; **done** or **blocked** as written.
3. If four or more rows of this file are running, end with "busy: <rows>" (usage is paced over two weeks; the 11-10
   queue's twenty does not carry). A session started for one named row takes that row only.
4. Pick the first row in the table below that is stalled, or else the first with no status file whose not-before has
   passed, whose needs are met, and whose inputs have not moved for 20 minutes. Between 22:00 and 06:00 pick only a
   stalled row (daytime UTC preferred). Nothing to pick: end with "nothing due" and the next row's not-before.
5. **Claim it**: on `claude/work-ledger`, write `docs/queue/<ROW>.md` (the schema below) with `state: started`,
   commit, `git pull --rebase`, push. If the rebase shows the file already changed by someone else, drop the claim
   and go back to step 4 once.
6. Do the row by its brief. A stalled row is a **resume**: read its Resume and its output branch, continue from what
   is pushed, never redo pushed work.
7. Finish: `state: done` (or `blocked`, with why), its outputs, a result of at most 15 lines, any owner decision
   last; update the row's line doc on the output branch (`docs/lines/<line>.md` §Open, its date). Push. End with a
   chat message under 200 words.

## No work lost (every row, every session)

* Commit and push to the output branch after every step that produced anything. Never hold more than about 20
  minutes of unpushed work. A measurement pushes its raw rows as they land.
* After each push, update the status file's `heartbeat` and **Resume** (done with commits, next, the exact commands)
  and push it. Before anything long (a build, a measurement, a big review), write the Resume first.
* When you sense the end (context, usage, a time limit), start nothing new: push, write the Resume, set `heartbeat`.
* Subagents push their own work the same way before they return.
