## 2 · Findings still open, ranked

### F1 · No cells — N6 cannot run on this harness

`client-runtime-experiment-plan.md` §3 now reads "N6 is no longer blocked on client wire or telemetry
plumbing". It is still blocked on the shell: no trace is driven, `D` is not held, and the bytes are not
used. The experiment plan §1 is explicit that a shell that only counts bytes does not exercise the
JS-heap copy under test. `verify_e2e.py --telemetry` today produces a well-formed report about nothing.

### F2 · Frame 0 is excluded by index, not by ask order

`report.ts` 104: `usable = frames.filter(f => f.frame_index !== 0)`. The rule exists for first-ask
warm-up. A trace starting at frame 40 keeps its warm-up row and drops a mid-run frame 0. Module fetch
and compile are already isolated into `connect_ms` (install → first ask); what lands on the first row
is server cold-page cost and first-stream setup, which is worth separating by ask time, not index.

### F3 · `long_tasks` is page-lifetime and structurally voids the WASM arm

`clock.ts` 48: the observer is `buffered: true` and unwindowed, so it counts WASM compile and
instantiate. The README voids a run whose `long_tasks` differs materially between arms; the WASM arm
will differ every time for a reason unrelated to the receive path. Every row still carries
`stall: null` (`rows.ts` 142) with no site, while the observer already has `startTime` / `duration`
per entry — overlap with a row's open window is exactly the evidence that the row's stamps are late.

### F4 · Refusals are invisible; a void run cannot be diagnosed

`proxy.ts` 105–128: `proxyBidi` intercepts `writable` only. `FrameError` on the control readable never
reaches the tap, so a refused frame leaves a row open forever. `verify_e2e.py` now fails the run on
`rows_opened != rows_closed` (good), but the report cannot say which row or why. Rows have no
`outcome`; the server row has `locate_outcome` / `write_outcome` and the client has nothing to pair.

### F5 · Copy evidence is a declared constant

`copies.copies_per_frame` is typed into the harness. It happens to be right (source read: TS copies
once in `ByteAccumulator.take`; WASM copies chunk → `RecvBuf` then `RecvBuf` → JS heap), but the report
presents it as measured. The experiment plan §5 asks for "transient allocation per frame"; nothing
samples it.

### F6 · Client `ring_capacity: 4096` describes a ring that does not exist

`report.ts` 13 and 169. Client rows are an unbounded array; the server has a real ring. Either enforce
or drop the field.

### F7 · Small stamp-fidelity leaks

- `tap.ts` 76–78: the FoD chunk is decoded and `JSON.parse`d **before** the `ask` stamp is taken.
- `tap.ts` 82: row kind is `frames.length > 1`; a `request_frames` carrying one index is classified
  as an interaction and `ask_granularity` follows it. The op is in the message.
- `ask_flush_us` is captured on every row and exported nowhere; the conflict branch at `tap.ts`
  91–94 is unreachable because `rowsNeedingFlush()` already filters on `ask_flush_us == null`.
- `wrap-session.ts` 38–46: the batch method stamps every frame `delivered` after the last arrives.
  Unused by the harness today; a row closed that way should say so.

### F8 · The two server-side files cannot actually be paired offline

The "no join product" rule rests on the two files being alignable by hand. Server rows carry
`frame_index` and `ask_ordinal` but no timestamp, so inter-ask spacing and batch position are
unrecoverable, and the summary has no `stream_mode`, `study` or `frame_count`. A `telemetry-server.json`
cannot be checked against the client file it sits beside.

### F9 · Three percentile implementations, two rules

`server/src/record/report.rs` and `client/transport-ts/record/percentiles.ts` — nearest-rank.
`lab/window-harness/src/metrics.rs` 277 — `ceil((n−1)·0.95)`. L1 quotes the harness p95; its brief says
L2 owns the fix and shaped runs must wait for it. It is not on this tree.

### F10 · Harvest is brittle where it matters

`verify_e2e.py` decides a run is over from log substrings, waits up to 5 s for the server Tap to flush,
then SIGTERMs. The server has no signal handler (`sink.rs` shuts down only from `Tap::drop`), so an
early SIGTERM loses the report silently — the script prints a WARN and continues. Run folders carry
no manifest; "never compare across `stream_mode` or cell" depends on filename discipline.

### F11 · The product `timing` object is still degenerate — flag only

`session.ts` 245–251 and `session.rs` `result_to_js`: `chunks: 1`, `firstChunkMs === lastChunkMs`, and
both harness pages print "wire ms" from it. With the external seam this is product code emitting a
wrong measurement. Product call, not this lane's.

## 3 · Decision A — recommendation: A4 as built, close it

| Criterion | A1 + A2 (in tree) | A3 (edit framing helpers) |
| --- | --- | --- |
| Stamp fidelity | `lastByte` at `read()` resolution before any copy; `delivered` at method return. An in-loop stamp would sit in the same event-loop turn — **no fidelity gained** | same |
| Arm parity | one JS patch, same bytes, same arithmetic — parity by construction | two implementations kept identical by review |
| Invasiveness | zero product lines | ~8 sites per client, gated |
| Default-build proof | "never added" | proven inert in two languages |
| Batch correctness | deterministic byte arithmetic; ask identity from the FoD op, not position | same |
| Cost (G5) | **measured: 1 µs per read at 320 frames** | small, but paid in product code |

A1's only real weakness was the parser cost, and that was an implementation defect, not a property of
the seam; it is gone. A2 alone cannot split wire from copy, so it stays as the `gesture` / `delivered`
half of the hybrid. Nothing identified needs a stamp inside product framing.

**What would reopen it:** a wire change that breaks byte-offset attribution (multi-frame envelopes,
compression), or a stage that can only be stamped inside `session.*`. Neither is on any plan.

**Amend the client ADR:** Decision A → decided (A4 = A1 + A2); record the measured cost; add the one
remaining seam gap — the control readable is not proxied (F4).
