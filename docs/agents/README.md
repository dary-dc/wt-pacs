# Agents

The rules every agent working here follows, supervised or not, each stated once. Read this file first, then the
one your work needs:

* [`queue.md`](queue.md): working a row of a queue unattended: picking, claiming, the status file, no work lost,
  where a row runs, which model takes it.
* [`reviews.md`](reviews.md): reviews, the fix loop, and who may write, build, run and judge a measurement.

The project's code, comment, doc and measurement rules are `CLAUDE.md`'s; they are not repeated here.

## Lines

Read [`../lines/<line>.md`](../lines/README.md) before working on a line, and update it before ending: state now,
open, any new decision, and the date at the top.

## Git

* Author and committer `dary-dc <crespoydelgado@gmail.com>`.
* A commit message holds only the change description: no Co-Authored-By trailer, no "Generated by" line, no session
  link. The same holds for a PR body.
* Push only your own branch, after `git pull --rebase`. Never force-push or rewrite pushed history.
* Never delete a branch or a tag, close a PR or remove anything without the owner's yes; a list for the yes is
  allowed.

## Branches, PRs and merges

* One question, one branch, one draft PR. Search the open PRs first: a question that already has a PR is answered
  on that PR's branch. A docs- or findings-only row writes to its line doc or one review file, with no PR unless its
  brief asks.
* Open PRs as drafts, through `mcp__github__create_pull_request`. The body names the question, the deciding
  measurement and the line doc it answers to, and holds only the change. Comment on a PR only where a brief says so.
* Never merge, except the merges the owner names. Nothing reaches `main` without review, and nothing reaches it
  uncleaned.
* A merge the owner names is a `--no-ff` merge of the branch itself, never a squash or a copy: conflicts are resolved
  in the merge commit, and cleaning is done by commits after it.

## Public repository

No private product or vendor names, nothing about any deployment host, no person's schedule, nothing from the
owner's local machine.

## Claims and data

* Every claim about a standard, browser, engine, codec, chip or tool is written with its official source quoted
  verbatim, as the docs will carry it.
* Label each number source, theory, derived or measured. Name the fixtures and their limits in every result.
* No probably-valid data is discarded: a rule may stop a run early, never exclude loads that ran under the
  protocol's conditions.

## Where work runs

* In the cloud, whenever the cloud can do it. Never ask the owner where to run.
* A step the cloud cannot do is recorded with its exact error and the complete commands for a local run; the row
  is set `blocked`, and the orchestrator schedules the rest.
* Phone runs are the owner's device session's, GPU runs are on the owner's machine, reader studies are no agent's.
  A row may write their protocols, never run them.
* A device round is fully automated: the owner opens one page and presses once, at the start; the runner drives
  every load, press and wait, and keeps the screen on and the page visible. Anything more asked of the owner is a
  defect.
