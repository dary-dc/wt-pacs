## 4. How the work runs

**Roles.** One orchestrator talks to Darian, keeps the decision table and the queue current, opens and merges PRs,
and starts workers. Each worker does one piece of work on its own branch and reports back. Only the orchestrator
opens PRs, merges, and writes the decision table; give each shared file one owner at a time.

**Brief for every worker** (paste it, with the task):

1. Read `CLAUDE.md` first and follow it: essentialist code, the comment rules and budget
   (`scripts/comment_budget.sh`, 0.18), docs in the file that owns the subject, every new test mutated (break the
   code, watch it fail, restore), measured variants interleaved.
2. Work in your own worktree or clone, on branch `claude/wip-<row>-<NAME>` made from
   `origin/claude/av1-unified-mainbase`, or on the existing PR branch you were given. Bring unified in with
   `git merge`, never rebase.
3. Commit as `dary-dc <crespoydelgado@gmail.com>`
   (`git -c user.name=dary-dc -c user.email=crespoydelgado@gmail.com commit …`), no attribution trailers. Push
   only your own branch, after every step. Never push to `main`, unified or `claude/av1-mainbase`; never force-push;
   don't open, close or merge PRs.
4. Before pushing: `scripts/gate.sh` (or `--quick`, or `--no-browser`, saying which). Known in cloud containers:
   `deploy/check_equivalence.sh --local` fails with nginx 403 when the checkout is under a 0700 directory, and the
   browser frame checks need the docker decoder build; CI covers both. Every other step must pass.
5. Builds are heavy: one build or test run at a time per host; a timed run never beside a build, one campaign per
   host. Install nothing beyond what the repo's scripts fetch.
6. Report: branch and head hash; files and +/− lines; what it removes and what it keeps; every check with its
   result and any skipped step; every mutation and that it failed; anything found and not fixed.

**Prerequisites a fresh checkout lacks** (git-ignored): decoder builds, hasher vendor, `node_modules`, the WASM
package, paint frames, a dev certificate. The repo's own scripts build them (`README.md`); the order is in
[`prep.sh`](prep.sh) (wasm-pack 0.15.0, `fetch_openjph.sh`, `fetch_xxh3.sh`, the transport WASM and TS builds, the
decoder build). [`kit.tar.gz`](kit.tar.gz) is a prebuilt copy from 2026-10-15; unpack it and copy its `kit/`
contents into the worktree, and rebuild it once the decoders or vendor scripts change.

**Merging a PR into unified** (only within rule 3.1):

1. `git merge-tree --write-tree origin/claude/av1-unified-mainbase origin/<branch>` is clean.
2. CI green on the PR head: `decoders`, `gate`, `deploy`.
3. If unified moved since that CI run, update the branch with a merge commit and wait for CI again.
4. Mark ready, merge with method `merge`, pinned to the head sha you checked.
5. Record it in the queue row and the decision table.

**Environment notes** that held in the old cloud containers: an HTTPS proxy with TLS inspection (docker builds need
`--network host`, the proxy variables, and the CA for cargo and curl); `CARGO_TARGET_DIR` shared across worktrees
means touching each worktree's tracked `*.rs`, `Cargo.toml` and `build.rs` before building; about 10 GB of disk.
