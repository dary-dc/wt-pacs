## Correctness review (medium effort, product code only, not verified by running)

1. `client/transport/downloader.js:234`: with `refill: "ask"` on the WASM client, the async `requestExactFrame` can reach the wire after the sync `fillFrames`. The server then ends the fill it just started and nothing re-issues the remainder until the stall timer fires. Only the non-default `ask` refill is affected.
2. `server/src/transport/websocket.rs:124`: a `set_nodelay`/keep-alive failure on one accepted socket is reported as an accept failure, so the whole accept loop sleeps 100 ms. Repeated connect-and-reset could hold accepts to about 10 per second.
3. `server/src/media/read_path.rs:424`: a failed pooled tile read leaves the slot keyed to the span with an empty buffer. Reading that span again would panic in `Bytes::slice`. Today the session ends on the first error, so it is latent.
4. `server/src/media/read_path.rs:438`: `ring.reap()?` drops completions already taken from the CQ when a later CQE in the same batch errors, so a later wait on that slot could park forever. Also latent for the same reason.
5. `client/transport/wasm/src/session.rs:554`: the WASM opening fill relies only on `?ask=fill:` in the URL. Against a server started with `--opening-ask false`, nothing is ever requested until the stall timer fires.
6. `client/transport/ts/frame-session.ts:186`: if `onHead` throws, the bare `catch {}` stops reading that media stream silently. The WASM client ignores the same error instead.
7. `server/src/media/read_path.rs:189`: an abandoned read-ahead's buffer is freed rather than returned to the pool. This costs efficiency only.
8. Comments name project history, which CLAUDE.md forbids: `read_path.rs:85` ("row 256's B1z"), `server/Cargo.toml:22` ("arm C1 of row 261"), `lab_frame_cache.rs:3` ("B1s").
9. `common/series-bundle/src/writer.rs:33`: the temp name is a fixed `NAME.partial`, so two packs of the same output collide. Only parallel packs of the same file are affected.
